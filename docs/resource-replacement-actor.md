# Protected resource replacement source

This candidate connects the ordinary same-account runtime-refresh transaction to
the host broker. It is inactive by default and has not been installed or accepted
by a native canary. The existing named laptop repair is separate evidence.

The optional website resource-purpose routes require a real current unrestricted
OwnerAuthService session and same-origin POST. They do not infer authority from
employee ownership, role labels, a digest, UID, forwarded headers or request JSON.
Undefined employee data ownership stays undefined. Apply binds the exact current
owner session to the selected employee, draft, operation, reservation, target SID,
profile version/digest and preview digest. Logout destroys the actual tracked
private channel; restart cannot recreate an executing context.

Preview accepts an employee and requested RAM only. The host derives the other
five resource fields and current source SID/generation from canonical data, writes
the versioned pending profile through ProfileStore CAS, then returns the exact
selected limits. Preview creates no operation claim, native allocation or positive
hold. A newer preview invalidates the old profile; an active employee claim
prevents rewriting it. Apply never rewrites the approved profile.

Apply retains the real journal handle in the broker and durably records PREPARING
before the normal SessionPort and expected-old CompanyService CAS publish the
target metadata. The normal runtime-refresh contract starts a fresh conversation,
clearing its old active resume selectors while retaining account, model, effort,
permission, environment and other runtime settings. Initial normal composer
readiness must precede sending the owner's explicit handoff. Clearing a resume ID
does not prove that the handoff was received or that conversation context survived.

The shared admission lock serializes RAM and fixed host-job admission with every
new canonical J preparation/creation. A private cached join routes the exact
normal Session command through the same broker cold preparation, sleeping
container, native binding, commit and CLI path. Ordinary J cannot consume a
reserved SID or recreate this join from wire identifiers. Source stop uses the
captured CID/PID/start and existing storage proof, including the protected
fallback-kill check. Unknown outcomes retain storage leases and the positive hold.

Actual canonical CLI release is required before STARTED. Normal Session readiness
binds both distinct outside attach and mux-pane PIDs, current Session and employee
binding, recipe, composer observation and actual move journal. VERIFY_RECORDED
continues to retain capacity. Native completion additionally requires the fixed
registered readiness producer, current kernel/cgroup/resource/account/storage
facts and the actual completed normal move record. Journal, store, lock and
descriptor finalizers finish before the pending marker's last unlink. A crash
that resurrects the marker refuses admission until protected reconciliation.
Historical completion never treats an old PID as current or credits freed source
memory; every later admission observes actual current native commitments.
The final pass binds current journal, employee/profile, policy and receipt bytes
and file/ancestry identities after descriptor finalizers. An orphan pending marker
cannot be hidden by an empty journal. A lost reply after known native settlement
may leave server-side recovery, but cannot recreate an executing handle or replay
effects. Resource-purpose replies carry closed metadata summaries; private native
receipts and wide kernel identities remain on the host.

Source fixtures exercise real OwnerAuth, Company, ProfileStore, PlanMoves,
operation journal and broker adapter classes. Controlled wire, engine/kernel and
multiplexer ports are explicitly fixture observations, not installed receipts.
The connected endpoint fixture uses normal Session startup, shared command
builders, harmless owned processes and actual IPC, including terminal refusal
and cold recovery. No provider, engine or production instance is used.

Remaining acceptance includes the explicit installer-owned bootstrap producer,
full namespace-aware immutable website/client provenance, final package rebuild,
independent terminal-credit review, current owner/capacity admission and the native
replacement canary. Cold execution and cancellation remain conservative recovery;
they never replay the old handle. Original destructive temporary-space reclamation
and archive gates remain separate. No source result closes the full checklist.
