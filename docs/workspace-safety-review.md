# Workspace F1/F2 safety repair

Source-only repair in `codex/workspace-safety` at base `7d6321f`. Original completed feature work is preserved. No production API, host/container controls, deployments, credentials or private memories were accessed. Root coordinates the owner-authorized rollout and fresh independent review.

F1 now uses a publication authority that does not depend on renameable directory paths: uploads accept only the empty relative directory (workspace root), with a sanitized single basename and atomic no-overwrite link. The default verifier requires the configured path to already be canonical, the root FD's kernel mount ID to name exactly that mountpoint, a non-root uid/euid with no effective Linux capabilities, and a root-owned ancestor chain with no group/other write bits, opened with O_NOFOLLOW. It confirms the pinned/current root inode identity. A mounted root cannot be renamed by shared-drive writers. Root ownership of the mounted directory itself is not required. Ordinary roots remain browsable with an explicit uploads-disabled reason. No permissions/mounts/uids are changed.

F2 now admits one operation process-wide across every WorkspaceFiles instance and list/file/upload method. Its deadline starts before root lookup. Shared-root IO, including authority metadata, uses sequential asynchronous calls with a runtime single-IO assertion. A timed-out caller returns while admission remains held until the actual uncancellable work and cleanup settle. Late acquired handles and temporary files are registered before abort checks, so late completion cannot skip cleanup. New IO stops after abort except required serialized cleanup. Canonical parent/target/final paths also reapply generic hidden/control policy before a read/list capability is returned; moving a directory after a read capability is granted does not revoke that capability. Configured libuv pools below four fail closed. This bounds the workspace contribution; unrelated legacy filesystem budgets are separate.

Downloads close the file descriptor before EOF and release admission synchronously only after the stream has been fully consumed and no IO/handles/cleanup remain. This preserves an immediate next GUI action. Premature stream completion aborts the operation promptly, including a silent close while backpressured; pending IO and close still retain admission until settled.

Commit deadline contract: no publication is issued after late setup/write completion. An already-issued atomic link cannot be canceled and can finish later in the verified authorized root. The caller gets `408: Upload confirmation timed out; file may have arrived. Refresh before retrying.` Admission stays held through the real commit and cleanup. No post-link deletion rollback can race another writer's replacement. Underlying cleanup can itself stall; there is no unconditional completion-time guarantee.
