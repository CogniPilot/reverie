# Fixed public browser jobs

This optional source component supports one reviewed public capture. It adds no
service, account, permission, GPU grant, resource budget or enabled instance
configuration. Without `browserJobPolicy`, the host office phone refuses the
reserved `/api/browser-jobs` path with503. It never forwards that path as a
general console request.

The owner-selected private policy is a canonical0600 file outside every worker
mount, including stopped, broad and read-only mounts and namespace aliases.
`browser_job_policy.py` defines its closed schema. It binds one employee/session
generation and account recipe, one standing server-marked owner cue, an exact
reviewed capture and manifest, asset hashes, hardware UUID and adapter identity,
immutable tools and runner, and finite limits. It is configuration, not an owner
assertion accepted from the worker. The reserve field must match the canonical
resource reservation policy; it never creates a second budget authority.

After separately reviewed installation, the selected member posts the exact
`/browser-job slam-office640` text through normal `reverie agent chat say`, as a
reply to the selected standing cue. `python -m reverie.browser_job submit MID`
then sends only that canonical request reference over the existing office phone;
`inspect` and `cancel` use the same reference. No caller-selected URL, source,
actor, command, PID, credential, cookie, output path or browser endpoint exists.
The host uses the phone's captured SID and the normal authenticated chat source,
current employee/account/generation, membership, owner mark and website epoch.
Historical sender metadata proves a source SID, not its historical generation.

The shared reservation gate must be installed and qualified. Its fixed host-job
ports bind the actual policy and full candidate, publish a durable intent under
the existing admission lock before scope effects, and fence new creation until
actual registered scope settlement. Reattach is not permission to create. A
removed option or lost response cannot clear a fence. The proposed job memory is
never a reservation or a promise of current capacity; insufficient conservative
pool/site/kernel/ancestor headroom refuses without changing peers or budgets.

The broker thread holds the canonical workspace operation and lease outside an
ordinary user scope. The scope has private CPU selection, memory/no-swap/task
limits and an independent runtime/stop bound. A private pipe allows the fixed
Node runner to renew current authority. Browser launch waits for actual native
scope capture and binding. Tools and source must be immutable installed bytes;
the optional `browserJobRuntime` package supplies only Playwright/core and the
fixed driver/runner, with no console build dependency or automatic installation.
Its evaluation or source tests do not establish a working GPU.

The driver requires actual native sandbox reporting, process ancestry/cgroup and
seccomp facts, a hardware ANGLE/Vulkan renderer, and bracketed native GPU
PID/index/UUID observations. An index alone is not device identity. It loads only
the selected HTTPS origin/path and reviewed GET/HEAD assets, refuses redirects
and WebSockets, caps streaming responses, and records original/hook/transformed
worker hashes. The approved640x360/5Hz capture controls scientific parameters;
this integration does not modify thresholds or interpret the result. The job
does not claim OS-level network confinement, exclusive GPU access or benchmark
throughput.

Setup and capture phase clocks close the own browser on expiry; the independent
scope runtime is the resource backstop. Absolute deadlines also bound control
queries and cleanup. All streams, direct children, descriptors and workspace
finalizers precede common-gate release. A locally written result or an empty
cgroup alone cannot release capacity: the fixed observer must recheck the actual
registered incarnation, reaped direct client and all retained process births.
Unknown outcomes remain fenced and are never retried automatically.

Only sealed regular files from this job's capture/proof directories are returned
through the existing authenticated room upload/message routes. A bounded gzip
tar stream has relative names and at most one16MiB part buffered; each message
attaches at most ten parts and replies to the original request. A delivery intent
precedes upload. Lost upload/post acknowledgments remain delivery-unknown with
no retry; successful capture is distinct from artifact delivery and scientific
acceptance. Exporting artifacts exposes no arbitrary host-file interface.

Native installation remains an explicit gate: current immutable broker/module
closure, actual full HostConfig and all mount grants, protected policy/control
custody, user bus/runtime support, canonical reservation producer, real selected
GPU/tool/ICD/sandbox facts, current capacity, and normal phone/client availability
must be reviewed. This source neither installs those facts nor enables a live
job. Host NixOS, administrator elevation, new root daemons, private credentials,
worker identity/account changes and scientific acceptance are outside this slice.
