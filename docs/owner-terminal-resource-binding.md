# Laptop terminal and resource replacement compatibility

A newly prepared H generation uses installation policy version 2 when the
canonical resource reservation control is configured. The owner still selects
an explicit stable employee ID set. Each selected employee retains its original
canonical data-owner digest; the current SID/generation comes only from the
fresh company row. OFF, vacation, migration, ambiguous binding and owner changes
refuse. A previously issued SID/generation capability is never retargeted.

The private policy retains its exact initial configuration and R control binding.
H excludes exactly the six fields in `worker_resources.RESOURCE_FIELDS` and the
`employeeResources`/`sessionResources` projections from its *authority* digest.
Image, GPU grants, browser policy, capability paths, owner scope, storage and all
other fields remain strict. Excluding a field does not approve a changed value.

Changed resource bytes must be reachable from that initial configuration through
real canonical operation records, their profile-bound private drafts, PREPARED
configuration receipts and configuration-before/attempt records. H reconstructs
the same profile projection and OLD six-field compatibility candidate, preserving
unrelated entries. A PREPARING/unknown publication, missing receipt, orphan
settlement, changed marker or custody and corrupt canonical stores refuse.
Completed history uses the existing protected settlement validator, without
reviving a claim, authorizing a native effect or crediting capacity.

These observations use the existing cross-process admission lock. Canonical
store readers and native custody bracket the observation; the complete private
history leaves, ancestry and final current config are checked after native and
lock finalizers. External mutation after its last observation is not atomic with
H. History decoding is bounded to 4096 entries, 256 drafts and 8 MiB per pass.

The H user service needs O_RDWR opens on the existing admission and operations
flock files. Its generated unit adds only those two pinned lock leaves to
ReadWritePaths; resource directories, journals, profiles and receipts stay
read-only. Every H lifecycle base and selected generation root must be disjoint
from the actual canonical R root in both ancestry directions, including backing
and nested mount aliases. Constructor, guard and both unit-generation paths
check that purpose separation; the two lock files are the only exceptions.
It never creates missing locks or repairs R custody. Legacy version 1
and installations without R keep the original raw config SHA/inode and fixed SID
contract. Existing installed generations require a fresh reviewed generation to
select version 2; this source change performs no installation or migration.

Source controls cover real owned R config CAS, canonical broker launch and
protected completion, cold history reads, current binding/owner changes and
faults. They do not establish installed service, engine, PTY, provider or native
H+RAM acceptance; the complete deployment acceptance remains required.
