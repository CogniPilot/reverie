# Workspace files

The Workspace page lets the signed-in owner browse the company shared drive, preview files and transfer them without opening an agent terminal. See [the Work and scratch guide](../apps/web/src/web/public/handbook/work.md) for everyday use. This page records the implementation boundaries and verification.

## Behavior

The existing chat sidebar now has **Workspace** beside Board/Handbook. The embedded page provides folder browsing, breadcrumbs, Up/Refresh, filename/size/modified details, safe common UTF-8 text and raster image previews, download, and upload. Its **Back to chat** link closes the embedded page through a source/origin-checked message and preserves the unsent composer draft. Standalone use also has a normal Back to chat link. Relative page URLs and the new navigation entry honor the existing base-prefix setting.

The only root is the configured `sharedWorkspaceRoot()` (`REVERIE_SHARED_WORKSPACE_PATH`); requests cannot select another root. Every page/asset/API route requires a verified unrestricted owner cookie and rejects agent headers. Writes additionally require the existing same-origin check and a custom upload header; cross-site Fetch Metadata is refused. All routes are no-store, including explicit JS/CSS and HTML-alias handlers to bypass the static server's immutable caching.

Linux descriptors pin each path component with O_NOFOLLOW/O_DIRECTORY. Descriptor device and kernel mount IDs must match the root, including same-device bind mounts. No shell runs. Traversal, absolute/control/hidden paths, sensitive files, symlinks, hardlinked files and special files are refused. Broad home/private roots are refused. Filenames and preview text use DOM text; HTML/SVG are displayed only as plain text. Raster previews are sniffed PNG/JPEG/GIF/WebP, never active content.

Downloads and uploads stream exact bytes up to **32 MiB**; filenames use RFC5987 Content-Disposition. Uploads publish a single basename in the shared workspace **root only**, with no overwrite. The default publisher requires a canonical kernel mount root, a non-root user with no effective Linux capabilities, and root-owned ancestors without group/other write access. The mount root itself may belong to the publisher. These conditions prevent shared-drive writers from renaming the publication authority outside the root or into a hidden/sensitive subtree. An ordinary directory remains browsable but uploads are disabled with the reason. No mount, permission or UID changes are performed.

One process-wide workspace operation is admitted at a time across all list/preview/download/upload instances. Its 120-second default deadline starts before root lookup. Every shared-root filesystem call is sequential, and admission remains held until actual uncancellable work and cleanup settle, even when the caller has already timed out. Repeated requests receive 429 and do not issue more filesystem work. Pools configured below four libuv workers fail closed; the workspace contribution uses at most one outstanding filesystem job, leaving other workers available. Other application filesystem features have separate budgets.

Deadline expiry prevents issuing publication after late setup/read/write completion. An already-issued atomic link cannot be canceled: confirmation can time out while the authorized root publication completes. The response says **“Upload confirmation timed out; file may have arrived. Refresh before retrying.”** Admission stays held through the real commit and cleanup. There is no post-link deletion rollback that could remove another writer's replacement. Cleanup can itself stall; no fixed wall-clock promise is made for underlying filesystem completion. Late resources are closed and uncommitted temporary names are removed once the filesystem answers.

## Packaging and limitations

The browser regression is listed in `config/test-suites.ts` and runs with `npm run test:browser -- test/workspace-files.browser.test.ts`. The backend regression is included in the Nix console package's release checks. Build the application through the repository flake and deploy through the normal owner-controlled rollout; source validation does not activate a live release.

V1 deliberately refuses all symlinks, including owner-granted `--project` links, hardlinks and nested mounts, and requires Linux `/proc` descriptor support. There is no insecure fallback. The UI explains these limits. Text preview is capped at 256 KiB, raster preview at 5 MiB, transfers at 32 MiB; no archive/PDF/office execution or extraction, editing/deleting, folder creation, overwrite or host browsing. Folder scans are capped at 1,000 encountered entries and state when limited.

The existing shared-write trust boundary still applies: another process with filesystem write authority can concurrently modify an already-open file; this feature does not promise filesystem snapshots. Privileged concurrent mount changes and other host controls remain outside the workspace browser's authority. Filesystem cleanup can only be best effort if the filesystem itself refuses removal.
