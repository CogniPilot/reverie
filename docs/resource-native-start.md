# Private native start foundation

This foundation supplies private native start primitives. The optional integrated
source now composes them with the normal server transaction, as described in
[resource replacement](resource-replacement-actor.md). This lower module supplies
no owner authority or public endpoint itself. No production activation or native
canary follows from source fixture success.

The retained claim now captures original process/cgroup identity and physical
home/Nix/scratch identities through the fixed observer, linked to the already
approved source-binding/pool digests before admission's terminal checks. The
private publication-intent v2 retains those raw baseline facts. Cold lookup still
cannot recover an in-process handle or mint a permit from receipt JSON.

`_begin_start` validates the real PREPARED receipt, current policy, original or
proved-stopped source, target metadata/profile N and complete current native
capacity, then durably commits STARTING before effects. Its opaque permit is
bound to the exact controller/key, active handle, operation/reservation/target and
version four. It is not owner approval. Missing, removed or changed evidence
refuses; no caller-selected callback produces facts.

`_stop_source_once` records a durable source-stop attempt, uses the shared
canonical broker stop primitive with immutable expected CID **and original
PID/start**, then proves the source PID/cgroup released before releasing its
employee storage lease. A surviving PID, populated/unknown cgroup or changed
incarnation keeps the lease/fence and uncertainty. The optional canonical stop
path retains the unused source network rather than disconnecting/deleting a
possibly owner-replaced namespace. The omitted-argument legacy stop path stays
unchanged. A protected fallback kill requires the post-stop inspection to retain
the exact original metadata and PID/start incarnation; an observed replacement
refuses with the claim and storage lease retained. An already stopped protected
source receives no stop/kill signal.

The private launch permit admits at most one exact canonical admission, records
its attempt before effects and binds it to the held lock FD/thread. Ordinary J
frames retain reserved-target denial; JSON/header IDs cannot supply the object.
A creation check additionally requires the real target employee storage lease,
current finite host/site/peer facts and exact profile policy. This operation's
own positive hold is charged once as its candidate; it is not released for
unrelated allocations. Unknown retained peer assumptions never become credit.

The fixed `observe_created` producer reads actual CID/PID/start, effective kernel
RAM/no-swap/PID/CPU bounds, configured immutable image, labels and same physical
EID roots plus the current TMP bind. Original source release, unchanged peers,
policy file/in-memory agreement, native custody, journal/phase/receipt signatures,
profile and target metadata are bracketed and rechecked under admission. It
reports **RUNNING_CONTAINER_RESOURCE_FACTS_ONLY**, explicitly not CLI readiness,
owner verification, STARTED/VERIFIED journal ACK or released capacity. Controlled
engine/kernel fixtures are not live host acceptance.

The integrated source joins the existing J cold preparation/creation/CLI path,
including the Nix helper, retained TMP and sleep-before-commit ordering, and records
created CID only from that producer. Normal TS SessionPort/CompanyService performs
the approved recipe and binding CAS. Installed current-owner/session proof,
immutable website/client provenance and native service custody still require
their separate qualification before any effect entry is activated.

Actual STARTED and VERIFY_RECORDED require real creation/CLI and native/server
readiness evidence. Protected finalize must follow durable server completion and
fresh native observation; a receipt hash alone never releases the claim. Terminal
accounting/cancellation, cold reconciliation and selected native acceptance stay
open. The original destructive scratch-reclamation/archive gates are separate.
