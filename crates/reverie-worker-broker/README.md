# Native worker broker integration

`reverie-worker-broker broker --config PATH` uses the actual owner configuration
loader, one installing Runtime, recovery-before-listen, the existing bounded
report registry, and published actual handler JoinHandles. It never executes
itself or replaces its process image. Replacing this program invalidates its
original-process delegation and requires supported registered bootstrap.

The additive `nativeWorkerBroker` Nix output is explicitly selectable; the
default `workerBroker` output still selects the legacy implementation. Supported
native service install/upgrade can select a native package independently of that
default. Check actual executable provenance separately from source availability.

The service connects ordinary J preparation, Cold/Reuse viewer relay and
all-outcome finalization, M/G consumers, Q fleet maintenance and pool B
registration. Qualified Q `migrate-pool` uses the retained installation offer,
actual original-handler/fleet settlement, checked controller activation and
configuration/domain/actor publication. Other resource-replacement continuations
remain separate; protocol dispatch alone establishes no installed policy.
C supports the fixed `status`, `provider-health`, `storage-status`
and `stop-laptops` actions. The first three observe; the last stops and settles
the fleet once. It does not retain writer exclusion for a later snapshot and
does not change employees' desired-running choices. Unknown C actions refuse.

Protected L and resume Y dispatch, coordinated website maintenance and full
installed resource-policy acceptance remain separate migration requirements.
Fail-closed missing-consumer handling is not completed protocol support. Passing
an ordinary launch or reconnect test does not establish all-verb readiness.

Retained J cleanup stays on the original counted handler thread. Its closed
Status/Reconcile inbox belongs to the same HandlerJob. Late reconciliation
polls only original native owners and can resume socket/Hold bookkeeping only
after the original resource phases actually finished. Historical errors remain
negative diagnostics; uncertain effects, consumed-close outcomes and failed
observations cannot be reset by a response or thread join. Service shutdown is
negative while actual Box, Office, handler or native owners remain unresolved.

The same binary has a build-only `origin-manifest` role with no supplied paths.
Nix compiles its fixed executable/manifest output slots, then invokes this role
in `postFixup`, after stripping and RPATH changes. The exclusive, synced manifest
therefore hashes the final installed ELF without a derivation dependency cycle.
It supplies origin DATA, not installation consent, Q authorization or a pool
activation grant. Neither policy-version publication nor GUI policy activation
may restart or rebind the delegated broker process.

## Owner bootstrap commands

These commands use the same native application services as their callers. They
accept an existing registered owner configuration; they never confer website
administrator access or replace explicit resource-owner consent. Use each
subcommand's `--help` for its complete arguments.

`actor preview --config PATH` observes the actual website using the packaged
provenance, image, code and process readers. It returns a preview digest after
closing the original inspection. `actor apply --config PATH --expected-preview
SHA256 --operation-id UUID` prepares a fresh preview and installs only that exact
initial actor identity and configuration/domain transition. Apply requires the
registered native service to be inactive. It preserves employee policies,
session identities and supported history; it does not start the service,
recreate workers or install a shared resource pool. The website must already
match the protected profile and the immutable packaged provenance. There are no
caller-selected process, socket or provenance overrides.

`pool prepare-nomination-v1 --config PATH --enrollment FILE` derives a proposed
pool nomination from an explicit enrollment response, current company/settings,
checked actor facts, matching loaded factory images and the actual CPU set.
Existing finite soft memory highs are retained; otherwise the current hard
ceiling is returned as a **proposed** soft high. The output includes these
fallback identities and the full proposed policy. It grants no permission to
install the controller. Nonzero swap or incomplete company bindings refuse.
`pool nominate-v1 --config PATH --request FILE` is the explicit closed-document
import interface; normal setup can use the derived nomination instead of
constructing that document by hand.

Service install/upgrade accepts the closed `--role broker|offer-pool-v1`
selection. The default remains `broker`; the other role uses a second immutable
packaged recipe and the fixed account-home nomination. Prepare the website,
enrollment and loaded factory inputs before starting its temporary offer. Then
use the authenticated fleet preview and explicit Q `migrate-pool` consent. Do
not consume the offer through B installation consent first: that installs the
controller and consumes the offer required by Q. Enrollment response DATA and
installation consent are separate operations.

The [console deployment service](../reverie-deployment/README.md) owns the
explicit protected-website profile, writer checks, verified snapshot and
activation workflow. Loading an image, compiling these commands or publishing
an actor document does not establish an installed website or shared RAM policy.
