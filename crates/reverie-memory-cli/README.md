# Installed memory bridge candidate

`reverie-memory` reads one path-free screen/recall/remember JSON request from
stdin. Instance selection belongs to the installed bootstrap (`--instance` or
`REVERIE_INSTANCE_CONFIG`), not the request. This candidate is not selected in
the runtime package. Namespace observations and installed configuration do not
authenticate a caller or grant access to another employee or project.

Recall requires explicit initialization. Missing state returns NotInitialized;
recall does not import, seed, create profiles, reembed, or repair a selected model.
`--initialize` is the explicit, idempotent lifecycle operation. The real launcher
must establish its authenticated employee/project scope and call startup before
runtime selection. Startup and recall share actual namespace checks and a fixed
flock; this does not coordinate legacy Python writers during a split cutover.

Remember applies the same qualified fixed private-person floor, then invokes the
supported `reverie agent journal save` API client in its captured session. Room,
turn, quote/reference and tag come from the request; nothing guesses a source.
No direct write to the legacy memory database is used. A missing session/source
returns a copyable command. A lost or malformed post-dispatch reply is an
unconfirmed save, never “nothing was saved,” and is not automatically retried.
Native client cleanup finishes before response publication. Process uncertainty
retains the same actual client rather than starting another one.

The candidate binds the canonical Nix Node executable and the console's raw
TypeScript CLI entry at compilation. It does not select a `reverie` wrapper from
PATH, read an executable override from the environment, or fall back to Python.
A developer build without those package facts refuses a requested journal
operation; recall outside a session still reads only its initialized legacy data.
The TypeScript client retains the supported session/credential-file authentication
flow. The server checks the current employee, readable turn and every quoted source.
The reused console output still carries its existing shell source files for other
commands; this binding does not retire that broader console migration debt.

MCP may receive a checked native executable binding from the final installing
runtime, which owns both console and memory without a build dependency cycle.
That constructor is executable-origin data, never an employee/project grant.
The native screen/read child receives captured model, proxy and screening settings,
including owner rules, while session and journal credentials stay in the MCP
process. The existing MCP runtime selector remains unchanged until the real
authenticated installation scope producer is implemented and reviewed.

Shutdown distinguishes completed close, pending native work, and consumed
negative finalization. Constructors, unreaped children, held descriptors and
unknown owner state remain pending. A consumed failure still keeps the library
fenced and produces a negative standalone exit after remaining finalizers;
polling an irreversible error cannot acknowledge cleanup. An unconfirmed API
save remains unconfirmed in every shutdown state.

Configured owner regex patterns remain a required compatibility dependency.
This candidate refuses a nonempty rule set until a Python-compatible native
adapter is independently qualified; it never silently omits rules or substitutes
a different regex language. The fixed floor uses shared frozen Unicode facts and
actual Python differential fixtures, not an arbitrary regular-expression VM.

Intentional corrections needing review before selection: request fields are
closed (no path/model/private-store editor); read-only recall and journal saves
do not trigger hidden ChatDaemon startup mutations; journal success requires the
actual success/data envelope; ASCII-escaped JSON output can represent surrogate
codepoints that failed legacy stdout encoding. JSON decoders may combine adjacent
high/low surrogate escapes, so decoded codepoint identity is not guaranteed for
those pairs. Existing Office journals remain distinct
from the legacy employee/project memory tables and Handsroom data.

The journal transport uses the common retained process owner. Its 60-second,
8 MiB combined transport policy is separate from embedding HTTP semantics and
the broker metadata capture policy. Launch/auth binding, configured endpoint-scheme
inventory, owner-regex compatibility and coordinated single-writer cutover remain
required. Host child fixtures qualify retained transport behavior; the console's
`native-memory-journal-api.test.ts` qualifies actual clients, enforced middleware
and policy, current company/source stores and durable journal behavior using
synthetic accounts. Its native artifact cases require the explicit test-only
`NIX_REVERIE_TEST_MEMORY_CLI` qualification path; a normal TypeScript test run
does not claim native package or installed scope acceptance. Neither test mode
proves a live company migration or grants a caller access.
