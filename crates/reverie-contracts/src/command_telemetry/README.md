# Command telemetry contracts

One Core TelemetryKey/configuration vocabulary is reused by ordered full worker
validation and the actual optional collector. This module lazily projects its
constructor source list, final MetadataText argv, filtered 12–64 lowercase-hex
engine references and complete Mounts rows. It never derives an employee from
an engine ID or turns configuration/argv into an effect permit.

Inspect uses default json.loads(str): last-wins, nonfinite unrelated data and the
frozen integer conversion policy. Events use the distinct default bytes encoding
and duplicate-hook policy, with a 512-byte closed shape, canonical UUID including
nil, selected tool/UNKNOWN_COMMAND and nonzero integer exit -255..255. Requests
use the protected report's distinct strict 4096-byte shape. No generic JSON editor,
new tokenizer, host command, path resolver or global worker validation is added.

Report building verifies employee identity, known selected tools, unique groups,
2048 total/count bound, source sort/truncation/counters and 256-KiB encoded limit.
Unreadable/invalid reports become unavailable, not successful empty data. Named
writers reproduce exact original compact JSON key order using only checked UUIDs
and closed ASCII vocabulary. Host caller authorization, current storage/owner
observations and dedicated SQLite custody remain their existing separate owners.
