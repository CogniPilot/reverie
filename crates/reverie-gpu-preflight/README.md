# GPU preflight

`reverie-worker-gpu --config FILE --employee UUID --device NVIDIA_CDI_UUID`
preserves the standalone metadata preflight interface, optional `--image`,
`--browser` and `--cdi-sha256`, its report fields and exit 77 refusal.
The installed package compiles the Docker client path; callers cannot choose a
program, command, environment overlay or fixture path.

The application uses the original private configuration reader and full worker
validation, current-only employee resolver, exact physical UUID spelling, CDI
policy, image protection, effective resources, laptop inspection and process
identity. It repeats the original observations before accepting the report.
The native client shares the captured-process supervisor and checked cleanup;
each fixed query has eight seconds and one MiB of stdout, with stderr discarded.
JSON byte encodings and complete path values remain distinct from the queue's
numeric-node projection. The final configuration read precedes finite report
serialization and its 64-KiB limit.

This command reads metadata. It does not configure drivers, grant device access,
create workloads, start services or change laptops. A successful report does not
qualify GPU compute/rendering or enforce a VRAM quota. Python remains available
as an employee programming tool; the old Python preflight module remains while
other legacy services import its helpers.

Typed arguments refuse before metadata queries. Malformed metadata returns the
fixed refusal instead of exposing an interpreter exception. Safe YAML float
construction now evaluates exact integer multipliers in reverse sexagesimal
order; multiplier overflow refuses the whole document, matching PyYAML even in
ignored values. Earlier native validation checked only the individual terms.
